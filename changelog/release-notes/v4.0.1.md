# v4.0.1 — Native dispatch works with the published Substrate package

Package: `@jaggerxtrm/specialists` · Version: `4.0.1` · Previous: `4.0.0` (2026-09-28)

## Summary

4.0.1 fixes native Specialist dispatch on machines where `@jaggerxtrm/substrate`
is installed from npm rather than linked to a source checkout. Upgrade if
`specialist_dispatch` refuses with:

```text
work_item_store_unavailable: cannot load Substrate module src/store/migrations/runner.ts
```

## Fixed

- **Native dispatch with published Substrate builds** (#415). Specialists loads six
  Substrate modules (the migration runner, the issue, journal and provenance services,
  the work-item store and the dispatch gate). It looked for them only by their
  TypeScript source paths, but the published `@jaggerxtrm/substrate` 0.2.2 package
  ships only prebuilt `dist/src/*.js`. Every Specialist was refused before a model
  turn. Each module now resolves to `src/<module>.ts` in a checkout and to
  `dist/src/<module>.js` in a published package. Package identity and required
  exports are still checked, and any failure is still refused.
- `specialists doctor` checks the same two layouts. It now reports a Substrate
  package as broken only when neither layout contains a required module.

## Security

- **The host-read isolation waiver is renewed for 4.0.1** (`unitAI-641h0`,
  operator-approved 2026-10-01, same terms). Specialists still does **not** provide
  filesystem or host-read isolation. Runs, `sp script`, `sp serve`, native MCP
  activations, Pi extensions and child processes can read anything the runtime OS
  identity can read. Use Specialists only with trusted, single-tenant callers. The
  waiver expires at 4.0.2 or on 2026-10-31, whichever comes first, unless a release
  enforces host-read isolation before then. The release attestation receipt does
  not authorize publication.

## Upgrade

1. Update the package to 4.0.1.
2. Run `specialists doctor`. Under the Substrate section it reports the package as
   resolved, whether it is a checkout or a published install.
3. In Claude Code, run `/reload-plugins` so the specialists MCP server loads the
   new build.
