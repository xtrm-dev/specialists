# v4.0.0 — Native Specialists: in-process activation, Claude Code and Pi as first-class hosts

Package: `@jaggerxtrm/specialists` · Version: `4.0.0` · Previous: `3.21.6` (2026-09-03)
Range: `v3.21.6..v4.0.0` · ~505 commits · PRs #283–#413

## Summary

4.0.0 makes **native activation** the primary way to run a Specialist. A
Specialist now runs as an in-process Pi `AgentSession` hosted by the MCP server
or the Pi extension your coordinator already runs, not as a spawned CLI job. The
work contract is a **Substrate Issue**: the Issue is the prompt, readiness is the
dispatch gate, and settlement is published back as durable evidence exactly once.

The same eight tools are available in **Claude Code** (the `specialists` plugin)
and in **Pi** (the `specialist-subagents` extension). Claude Code also gets a live
fleet band above the prompt, with reply, steer, resume and stop controls.

The `sp` CLI still works. It is now the operator and frontend surface, and it is
being migrated onto the native runtime (XTRM-93, nodes N4–N9). Until that
migration lands, prefer the native tools below for new work.

## Recommended ways to use Specialists now

### 1. From Claude Code: the `specialists` plugin (recommended)

Install the `specialists` plugin from the `xtrm` marketplace. It provides:

- **MCP tools**:
  - `specialist_list` shows the registry
  - `specialist_dispatch` starts an activation
  - `specialist_status` is the authoritative live read
  - `specialist_reply` answers a question by `message_id`
  - `specialist_steer` redirects a running activation
  - `specialist_resume` continues the same session
  - `specialist_retry` retries an activation
  - `specialist_stop_activation` stops and disposes an activation
- **The live fleet band** (a Claude Mod). It shows every activation this session
  dispatched, with state, model, turns, elapsed time and pending questions.
  - `/specialists show|hide|expand|collapse` controls the band.
  - `/specialists reply|steer|resume|stop …` acts on an activation without a tool call.
- **Channel-push wake**. When a Specialist finishes, fails or asks a question,
  the idle Claude session is woken. You do not need to poll.
- **The `supervising-activations` skill**. It is the operator procedure for
  dispatch → observe → answer → resume → stop.
- **Session continuity hooks**: SessionStart, PreCompact, PostCompact, and a
  lease warning on PreToolUse.

A typical loop:

```text
specialist_dispatch(specialist: "explorer", issue_ref: "XTRM-227")
  → activation admitted and started; the fleet band shows it
  → the Specialist asks a question → Channel push wakes you
  → specialist_reply(message_id, body) → it continues in the same session
  → settled → verify the result → close the Issue explicitly
```

### 2. From Pi: the `specialist-subagents` extension

Pi gets the same eight `specialist_*` tools, the fleet footer, and the `/fleet`
and `/specialists` commands. Pi also wakes the coordinator when a Specialist
finishes or fails (#294).

### 3. Contract first, always

A dispatch takes exactly one of the following:

- `issue_ref`: a READY Substrate Issue. `bead_id` remains a permanent alias.
- `contract`: an inline contract with PROBLEM, SUCCESS, SCOPE, NON_GOALS,
  CONSTRAINTS, VALIDATION, OUTPUT and SCRUTINY. That is eight parts, and
  SCRUTINY is the one most often left out. The inline contract goes through the
  same pipeline as an existing Issue: it is validated, created, attested and
  claimed, and then dispatched.

Draft, unready, blocked or scope-expanding Issues are refused before a model
turn is spent. Settlement is evidence, not Closure: close the Issue yourself
after you verify the result.

Per-dispatch options:

- `model_override` and `thinking_override` set the model and the thinking level
  for this activation only (#301, #303).
- `epic_context_depth` (1 or 2) adds ancestor Issue contracts to the prompt (#298).

### 4. Write-capable roles share your worktree under a lease

MEDIUM and HIGH tier Specialists (executor, debugger, test-engineer and others)
take the workspace writer lease at admission. A second writer is refused with a
structured reason. The lease is released at settle, on a rejected prompt, and on
a refused dispatch. It is re-acquired across a model-fallback walk and on resume
(#356, #358, #362).

## The CLI while it migrates

- `sp list`, `sp ps`, `sp feed`, `sp result`, `sp doctor` and `specialists doctor`
  remain the operator attention surfaces. `sp ps` now enumerates the latest N
  activations correctly, and `--mine` fails closed (#380, #385).
- `sp run <name> --bead <id>` and the Supervisor/worktree lifecycle are **legacy
  compatibility**. They stay reachable until XTRM-93 N4–N9 cut them over. Do not
  build new workflows on their Beads note, auto-close or worktree semantics.
- `sp merge` and `sp epic merge` are legacy. Git and Core own integration.
- `sp retry --model <id>` re-runs an activation with a different model (#312).

## Native runtime

- In-process native activation runtime, with identity lineage and an
  ExecutionBinding that pins issue, revision, hash, claim, participant,
  activation, session and workspace (#290, #335, #350).
- Automatic, bounded settlement publication, exactly once within a process and
  across processes (#360, #367, #372).
- Terminal-state truth in the native host (#346).
- Steering of running activations; tool output is compact by default, and
  `full: true` returns the verbose payload (#407).
- The inline claim and the created Issue are named on every refusal and released
  on refusal (#359, #362).
- Fallback engages on free-tier 429 limits (#312).
- `$resolved_tool_contract` is filled on the native path. Before this fix, seven
  Specialists were told to read a contract that was empty (#352).
- `npm:` extension sources resolve under native dispatch.

## Claude Code integration (Wave E)

- Strict MCP server on SDK v2. It serves both MCP protocol revisions (#313, #324).
- Channel push is the primary way to wake an idle session (#327).
- `specialist_status` returns a compact projection with no unbounded sections (#325).
- `substrate_issue`, `substrate_journal` and `substrate_provenance` tools (#329–#332).
  They register only when the Substrate service resolves, or when
  `XTRM_SUBSTRATE_TOOLS=1` is set. The dedicated Substrate plugin is the primary
  surface for Issue work.
- The plugin is named `specialists` and consumes Substrate; it is not Substrate
  (#337, #340, #345).
- Substrate resolves through module resolution and `SUBSTRATE_DB`, and the
  project resolves from the caller (#338, #344, #349).
- Live fleet band and controls as a Claude Mod (#405).
- Removed: the legacy foreground `use_specialist` MCP tool (#342), the legacy
  SessionStart hook installation (#333), and the injection of prohibited commands
  into every session (#328).

## Substrate is the work authority

- Beads is cut over: `.beads/` state and the bd hooks are removed (#409). Dead
  Beads coupling is removed from the native-facing runtime (#361). The bd-memory
  pipeline is retired from prompts, CLI, persistence, assets and docs (#311).
- Specialist definitions and mandatory rules now take their authority from
  Substrate (#412). Mandatory rules are inspectable (#413).
- Historical Beads IDs still resolve as aliases. `bead_id` and `--bead` stay
  accepted permanently.
- The native path no longer reports itself as complete when Substrate is absent.
  `doctor` distinguishes a resolved Substrate package from a loadable one
  (#368, #370).

## Fleet UI (Pi and Claude)

- Operational fleet view with per-message spend accumulation, a millisecond
  spinner and wake-message styling (#297–#307).
- Rows show the dispatch identity as `<specialist>:<activation-id>` (#375).
  Specialist tmux panes carry the dispatching pane's lineage (#383).

## Telemetry and observability (XTRM-93 N3)

- The native event mapper is total, so an unmapped event name can no longer be
  dropped silently (#382, #393).
- Authoritative Pi usage and cost are preserved (#394).
- Configured, requested and resolved model are persisted separately, and the
  fallback chain is proven end to end (#399).
- Phase accounting flushes open phases and re-enters `running` on resume
  (#388, #397). Tool-duration stale warnings, accumulated `elapsed_ms` and native
  metrics rows are recorded (#387, #408).
- `xtrm_llm_tokens_total` reads the shape the writer actually produces (#377).
- CI runs the telemetry-contract gate, the canonical N3 oracle and the
  `bun:sqlite` suites (#391, #392).

## Settings in `~/.config/specialists/`

No new persistent settings. Stale or ineffective settings are now reported
instead of ignored silently (#363):

- `beads_integration` and `beads_write_notes` affect only the legacy CLI. A
  native dispatch records a `config_notes` entry when either one is set to a
  non-default value.
- `specialists doctor` reports:
  - template fields that `user.json` lacks, for example `mandatory_rules`
  - retired keys (`execution.extensions.serena`)
  - extension keys that change nothing
  - enabled local-path extensions that do not exist
- The fix is `sp init --global`. It adds missing fields as inherit defaults and
  keeps every existing value. Nothing is removed automatically.

## Skill paths aligned with the Core v4 skill pool

- Definition skill paths match the overhauled Core pool: `default/` holds
  `engineering-quality`, `gitnexus`, `planning` and `using-specialists`, and
  `optional/` holds `research-methods`, `security-ops` and `xtrm-maintenance`.
  The retired `gitnexus-exploring` and `gitnexus-impact-analysis` paths are
  replaced by `gitnexus`.
- A bare skill name now resolves in this order:
  1. a project pack (`<repo>/.xtrm/skills/<pack>/<skill>`)
  2. the repo's own default root (`<repo>/.xtrm/skills/default/<skill>`)
  3. the global pool (`~/.xtrm/skills/default/<skill>`)

  Step 2 is new. It lets `service-knowledge-sync` find the `service-knowledge`
  skill that the xtrm `service-knowledge` package installs per repository, now
  that the global pool no longer ships it. A symlinked repo `default` root is
  skipped. A repo default skill directory without a regular `SKILL.md` fails
  closed.

## Security and CI

- **P0**: the self-hosted runner is retired from all trusted CI jobs (#336).
- Bun toolchain pinned to 1.3.14 (#317). Gitleaks baseline corrections (#286, #287).
- **The host-read isolation waiver is renewed for 4.0.0** (`unitAI-641h0`,
  operator-approved 2026-09-28). Specialists still does **not** provide
  filesystem or host-read isolation. Runs, `sp script`, `sp serve`, native MCP
  activations, Pi extensions and child processes can read anything the runtime
  OS identity can read. Use Specialists only with trusted, single-tenant
  callers. The excluded uses, compensating controls and prohibited claims are
  unchanged. The waiver expires at 4.0.1 or on 2026-10-28, whichever comes
  first, unless a release enforces host-read isolation before then. The release
  attestation receipt does not authorize publication.
- The CI package-payload check now derives the expected tarball name from
  `package.json` instead of a pinned version.

## Breaking changes

This is a major release because of the removals below. MCP clients that call
`use_specialist` and workflows that read Beads state from this package must
migrate.

- **Removed**: the `use_specialist` MCP tool. Use `specialist_dispatch` and
  `specialist_status` instead.
- **Removed**: the bd-memory pipeline and the `.beads/` state in this repository.
- **Inert under native dispatch**: `beads_integration`, `beads_write_notes`, and
  `execution.extensions.serena`, which is retired everywhere.
- `bead_id` and `--bead` remain permanent aliases for the Substrate Issue ref.

## Upgrade

1. Update the package.
2. Run `sp init --global` to bring `~/.config/specialists/user.json` up to the
   current template.
3. Run `specialists doctor` and act on its advisory lines.
4. In Claude Code, enable `specialists@xtrm`, then run `/reload-plugins`.
