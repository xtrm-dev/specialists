# v4.0.3 — Pi loads the coordinator tools without a settings edit

Package: `@jaggerxtrm/specialists` · Version: `4.0.3` · Previous: `4.0.2` (2026-10-01)

## Summary

4.0.3 makes the Pi coordinator extension load by default. Before this release,
the extension shipped inside the package but nothing registered it with Pi.
Each operator had to add a path to `~/.pi/agent/settings.json` by hand, and
that path usually pointed at a dev checkout instead of the installed package.
The extension is also renamed to describe what it is.

## Changed

- **The extension is renamed `native-specialists`.** The bundled directory is
  now `config/pi-extensions/native-specialists`. It was
  `config/pi-extensions/specialist-subagents`. The extension still provides the
  eight `specialist_*` coordinator tools and the fleet footer, unchanged.

## Added

- **Default registration in Pi.** A global install or update
  (`npm install -g @jaggerxtrm/specialists`) and `sp init --global` add the
  bundled extension directory to the `packages` list in Pi settings
  (`$PI_CODING_AGENT_DIR/settings.json`, default `~/.pi/agent/settings.json`).
  The step is idempotent:
  - An existing `…/native-specialists` entry is kept. A dev checkout wins over
    the installed package.
  - A legacy `…/specialist-subagents` entry is migrated in place: to the sibling
    `native-specialists` directory when it exists, otherwise to the installed
    package.
  - An unreadable settings file, or a `packages` field that is not an array, is
    never rewritten.
- **Opt-out.** To skip the install-time step, set
  `SPECIALISTS_SKIP_PI_REGISTRATION=1`. An install that runs with
  `--ignore-scripts` registers the extension on the next `sp init --global`.

## Fixed

- **Test isolation.** The `sp init --global` tests swapped `HOME` at runtime.
  Bun's `os.homedir()` ignores that change, so the new registration step could
  rewrite the developer's live Pi settings during a test run. The test setup
  now sets `PI_CODING_AGENT_DIR` to a temporary directory.

## Security

- **The host-read isolation waiver is renewed for 4.0.3** (`unitAI-641h0`,
  operator-approved 2026-10-02, same terms). Specialists still does **not**
  provide filesystem or host-read isolation. Tracked runs, `sp script`,
  `sp serve`, native MCP activations, pipelines, Pi extensions and child
  processes can read anything the runtime OS identity can read. Use Specialists
  only with trusted, single-tenant callers over private or loopback
  authenticated ingress, with minimal mounts and least-privilege credentials.
  Untrusted, public, cross-tenant and multi-tenant deployments are excluded.
  The waiver expires at 4.0.4 or on 2026-11-01, whichever comes first, unless
  a release enforces host-read isolation before then. The release attestation
  receipt does not authorize publication.

## Upgrade

1. Update the package: `npm install -g @jaggerxtrm/specialists@4.0.3`. The
   install registers the extension in Pi settings, or migrates an existing
   `specialist-subagents` entry.
2. If the install ran with `--ignore-scripts`, run `sp init --global`.
3. If your Pi settings point at a dev checkout, pull the checkout first, then
   run `sp init --global`. The legacy path stops resolving after the rename.
4. Start a new Pi session, or run `/reload` in a running session, so Pi loads
   the extension.
