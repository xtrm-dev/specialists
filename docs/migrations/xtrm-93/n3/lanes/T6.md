## Native evidence gaps and the “zero git invocations” claim

The strict end-to-end claim **no longer holds**. Native server construction opens the shared observability client (`src/server.ts:145-158`; the v2 server does the same at `src/mcp/v2-server.ts:98-116`), and DB-location resolution executes `git rev-parse --path-format=absolute --git-common-dir`, then may execute `git rev-parse --show-toplevel` (`src/specialist/observability-db.ts:18-41`). In addition, a native **reviewer** calls the shared reviewer diff hook (`src/activation/native-host.ts:1415-1446`), which executes `git symbolic-ref`, `git remote show`, `git merge-base`, and several `git diff` commands (`src/specialist/runner.ts:683-710`, `src/specialist/runner.ts:744-775`).

The narrower statement remains true for **workspace resolution itself**: `resolveWorkspace` performs no git discovery and returns raw `cwd` for both repository and worktree (`src/activation/native-host.ts:619-644`); the host binds only the workspace path (`src/activation/native-host.ts:1714-1722`). The native host has no current-branch, HEAD, base-ref, base-SHA or dirty-state producer in its activation projection (`src/activation/forensic-sink.ts:96-126`).

When the production observability DB is available, a native activation leaves these git/worktree-adjacent facts; the sink becomes a no-op when the DB is unavailable and all sink write failures are intentionally isolated from activation behavior (`src/activation/forensic-sink.ts:153-176`, `src/activation/forensic-sink.ts:247-250`, `src/activation/forensic-sink.ts:290-293`):

- The exact `cwd` used as `worktree_path`, normalized into `workspace_id`, correlated with issue (`bead_id`), activation (`job_id`), attempt and Pi session in the shared DB (`src/activation/native-host.ts:642-644`, `src/activation/forensic-sink.ts:92-126`, `src/specialist/observability-sqlite.ts:1491-1550`).
- For writers, a lease record with realpath-hashed workspace key, recorded worktree path, activation, attempt, specialist, PID/start ticks and acquisition time; this is runtime safety state, not the forensic DB (`src/activation/workspace-lease.ts:103-121`, `src/activation/workspace-lease.ts:181-206`, `src/activation/workspace-lease.ts:299-326`).
- A per-attempt settlement with issue/binding identity and output; its published execution context includes repo/worktree and may include an optional `binding.baseCommit` returned by the producer (`src/activation/settlement-store.ts:50-68`, `src/activation/native-host.ts:1797-1799`, `src/activation/native-host.ts:2147-2162`, `src/activation/settlement-publication.ts:198-208`).

It does **not** durably leave a current branch, observed HEAD SHA, dirty/clean status, worktree-registry entry, base ref, host-observed/pinned base SHA, behind count, auto-commit SHA, PR identity/drift, or branch-integration record (`src/activation/native-host.ts:642-644`, `src/activation/forensic-sink.ts:96-126`, `src/activation/settlement-publication.ts:502-510`, `src/activation/native-host.ts:625-640`). ## Workspace identity and normalization ceiling

Both engines reach the same observability normalizer through different producers: legacy supplies `SupervisorStatus.worktree_path` from `workingDirectory` (`src/specialist/supervisor.ts:1394-1418`), while native supplies `workspacePath` from host `cwd` through the forensic sink (`src/activation/native-host.ts:642-644`, `src/activation/forensic-sink.ts:96-126`). `workspace_id` is exactly `normalize(resolve(path))`; realpath, repository-root and git-common-dir normalization are explicitly forbidden so linked worktrees remain distinct (`src/specialist/observability-sqlite.ts:378-384`, `src/specialist/observability-sqlite.ts:682-693`). The known ceiling is equally explicit: a symlink spelling and its real path become different `workspace_id` values (`src/specialist/observability-sqlite.ts:690-693`).

That prohibition applies to the forensic `workspace_id`, not to lease exclusion. The native lease deliberately uses `realpathSync` before hashing so two symlink spellings cannot acquire two writer leases (`src/activation/workspace-lease.ts:181-197`). This is a valid semantic difference: observability preserves mutable-path identity; safety aliases equivalent paths (`src/activation/types.ts:33-45`, `src/activation/workspace-lease.ts:12-18`). A migration must not replace either rule with the other.

## Orphan / crash recovery telemetry

The prior legacy claim is verified. Every Supervisor run invokes `crashRecovery` (`src/specialist/supervisor.ts:1318-1323`); `readStatus` repairs a dead active job and emits/persists terminal evidence (`src/specialist/supervisor.ts:862-895`); every `loadStatuses` call reconciles terminal events and dead jobs before returning (`src/specialist/status-load.ts:266-335`). Legacy initial status records the supervisor PID (`src/specialist/supervisor.ts:1394-1403`).

The prior “native has none” claim needs one qualification. There is still **no native activation orphan reconciler**: the durable native status projection has no PID field (`src/activation/forensic-sink.ts:96-126`), and the live Fleet is process memory (`src/server.ts:126-134`). However, native now has **workspace-lease crash reconciliation**: dead/mismatched holders become `uncertain`, never free (`src/activation/workspace-lease.ts:244-256`), and an operator proposal is validated, appended to JSONL, optionally mirrored to forensics, and exposed by `specialist_status` (`src/activation/workspace-reconcile.ts:183-205`, `src/activation/workspace-reconcile.ts:292-367`, `src/activation/workspace-reconcile.ts:369-473`). This recovers mutation authority, not the activation lifecycle or result.

The prior dead-job SQL claim is verified. `listStaleSpecialistJobs` requires active status **and non-NULL positive PID** extracted from `status_json` (`src/specialist/observability-sqlite.ts:2459-2507`); `auditDeadJobs` only processes those rows (`src/specialist/dead-job-audit.ts:33-61`). Native `statusOf` never writes PID (`src/activation/forensic-sink.ts:96-126`), so native rows are invisible to that audit. `doctor cleanupProcesses` can classify a missing PID as dead in its DB-first loop, but this is a separate manual surface and not startup reconciliation (`src/cli/doctor.ts:838-878`, `src/cli/doctor.ts:1104-1151`).

A native orphan reconciler needs: (1) a durable host-process identity with PID **and process start guard**, because PID alone is unsafe (`src/activation/workspace-lease.ts:25-30`, `src/activation/workspace-lease.ts:103-108`); (2) a startup scan of nonterminal `act:*` rows; (3) a join to lease state, authority/binding and per-attempt settlement; and (4) a recorded decision that never infers completion from process absence (`src/activation/workspace-reconcile.ts:11-26`, `src/activation/workspace-reconcile.ts:128-148`). Status: **NATIVE_GAP**.
