3. **Claim 3 — `NATIVE_GAP`, and the stated filter set is false.** The native host has no watchdog, timer, `createStaleWarningEvent`, or `stale_warning` producer in the complete host/sink paths (`src/activation/native-host.ts:812-2780`; `src/activation/forensic-sink.ts:158-295`). ## 4. Phase arithmetic and worked resume example

### Shared aggregator algorithm

`aggregateJobMetrics` iterates timeline events and maintains `(phase, phaseStartedAtMs)` (`src/specialist/observability-sqlite.ts:2873-2900`):

- `run_start(t)` sets `phase=running,start=t` without closing a prior phase (`src/specialist/observability-sqlite.ts:2921-2924`).
- `status_change(running|waiting,t)` adds `t-start` to the old phase, then installs the new phase (`src/specialist/observability-sqlite.ts:2927-2933`).
- terminal status-change closes and clears the phase (`src/specialist/observability-sqlite.ts:2934-2938`).
- **Every** `run_complete`, including legacy `final:false`, closes and clears the phase (`src/specialist/observability-sqlite.ts:2942-2950`; non-final semantics are declared at `src/specialist/timeline-events.ts:266-277`).
- Therefore `active_runtime_ms = Σ(end-start)` for closed `running` segments and `waiting_ms = Σ(end-start)` for closed `waiting` segments (`src/specialist/observability-sqlite.ts:2885-2898`). There is no end-of-stream `closePhase`; an open phase is not counted (`src/specialist/observability-sqlite.ts:2956-2963`).

### Engine effects

- **Legacy:** Initial active time opens with `run_start`. Waiting and resumed running transitions are both emitted (`src/specialist/supervisor.ts:1500-1513,1858-1872`), but each per-turn `run_complete(final:false)` is emitted after the turn (`src/specialist/supervisor.ts:1608-1636,1888-1893,2598-2603`) and clears the waiting phase. Thus the long parked interval between turns is omitted. Resumed active runtime is counted because the running status-change reopens it. **`SEMANTIC_DIVERGENCE`** from the metric name/help.
- **Native:** Initial active time opens with `activation_started → run_start`; settle writes waiting then completion writes `run_complete` (`src/specialist/native-activation-observability.ts:242-270`). Resume produces no running timeline transition (`src/specialist/native-activation-observability.ts:50-56,241-306`), so neither the parked interval nor resumed active interval is counted. **`NATIVE_GAP`** relative to legacy.
- **Material additional gap:** Legacy invokes aggregation on terminal success/error/control (`src/specialist/supervisor.ts:1071-1076,2797-2799,2852-2853`; `src/specialist/control.ts:136-146`). The complete native sink only writes status/events/results and never invokes `aggregateJobMetrics` (`src/activation/forensic-sink.ts:158-295`). Native metric rows therefore normally do not exist until an explicit DB aggregation/prune path runs (`src/specialist/observability-sqlite.ts:3203-3217`). **`NATIVE_GAP`**.

### Worked example

Assume exact event times in milliseconds:

```
0      run_start
10_000 status_change running→waiting
10_000 run_complete for attempt 1
30_000 native activation_resumed (status row only; no timeline event)
50_000 status_change running→waiting from attempt 2 settle
50_000 run_complete for attempt 2
```

The aggregator reports `active_runtime_ms=10_000`, `waiting_ms=0`: the first run-complete clears waiting at 10,000; resume does not open running; the second waiting transition opens and closes at 50,000 (`src/specialist/observability-sqlite.ts:2921-2950`). Semantic time is active `0–10,000 + 30,000–50,000 = 30,000 ms` and waiting `10,000–30,000 = 20,000 ms`. Native active is low by 20,000 ms **and waiting is also low by 20,000 ms**. It does not absorb the resumed interval. A legacy resume with the same boundaries reports the second 20,000 ms active segment because it emits waiting→running (`src/specialist/supervisor.ts:1858-1866`), but still loses the parked waiting interval because the non-final run-complete cleared it.

### Prometheus counterparts

Prometheus performs no independent arithmetic. It divides stored milliseconds by 1,000 (`src/specialist/prometheus-projection.ts:847-850`), exports terminal rows’ `active_runtime_ms` as `xtrm_job_active_runtime_seconds` (`src/specialist/prometheus-projection.ts:143-173`), and exports all metric rows’ `waiting_ms` as `xtrm_job_wait_seconds` (`src/specialist/prometheus-projection.ts:198-207`). It therefore reproduces the SQLite errors exactly; absent native metric rows produce no native histogram observations. The current test oracle proves only the idealized sequence with explicit running/waiting transitions and one terminal run-complete (`tests/unit/specialist/observability-sqlite.test.ts:1115-1143`) and does not cover resumed native attempts.

## 7. Canonical representation and compatibility constraints

### Canonical transition semantics

1. Treat `starting`, `running`, and `waiting` as **job/activation phases**, independent of snapshot presentation states such as `settled`, `needs_reply`, and `escalated`.
2. Persist every phase edge as the existing shared timeline value `{t,seq,type:"status_change",status,previous_status}` (`src/specialist/timeline-events.ts:230-234,811-820`). Its forensic mirror must remain `event_family:"job"`, `event_name:"job.status_changed"`, with the original timeline object under `body.legacy_timeline_event` (`src/specialist/forensic-events.ts:576-621,791,813-840`). Consumers must read the payload.
3. Initial execution opens with existing `run_start`; explicit resume and explicit retry must append `status_change(...→running)` at the moment work can run. Native already updates the status row on resume (`src/activation/forensic-sink.ts:69-72`) but needs the timeline edge. The adapter must derive `previous_status` from the projection state, not hard-code waiting, because resume is allowed from `settled`, `waiting`, `needs_reply`, and `escalated` (`src/activation/registry.ts:93-104`).
4. A resumable turn completion must not terminate the waiting phase. Legacy already marks per-turn completion `final:false` (`src/specialist/supervisor.ts:1623-1636`); the aggregator must not clear phase for `final:false`. Native currently emits every successful `activation_completed` as `final:true` even though the host deliberately keeps the session resumable (`src/specialist/native-activation-observability.ts:251-270`; `src/activation/native-host.ts:2125-2126`). Native therefore needs an explicit distinction between attempt/turn settlement and activation finalization before phase parity is possible.
5. Use `(job_id/activation_id, attempt_id, seq)` as the comparison key. Native resume/retry advances attempt ID (`src/activation/registry.ts:81-90`; `src/activation/native-host.ts:2383-2405,2726-2747`), while legacy resume does not and legacy auto-retry advances only at `retry/start` (`src/specialist/observability-sqlite.ts:390-392,1629-1647`). This is a **`SEMANTIC_DIVERGENCE`**: either synthesize a legacy resume attempt boundary or compare resume legs as turns rather than attempts.

### Byte/backward-compatibility constraints

- Do not add a native-only lifecycle event family. The adapter contract intentionally uses the shared timeline and forensic vocabulary (`src/activation/forensic-sink.ts:1-15`; `src/specialist/native-activation-observability.ts:38-49`).
- Preserve the exact status-change keys/types and `job.status_changed` name; add behavior by emitting another canonical row, not by renaming existing fields (`src/specialist/timeline-events.ts:230-234,811-820`; `src/specialist/forensic-events.ts:813-840`).
- Preserve `status_json` as the serialized `SupervisorStatus`, its separate queryable `status` column, and existing identity columns (`src/specialist/observability-sqlite.ts:1491-1550`). Do not rewrite historical blobs; V15 explicitly treats blobs as original forensic records (`src/specialist/observability-sqlite.ts:682-701`).
- Preserve monotonic per-job sequence allocation and `attempt_id` on both timeline and forensic mirrors (`src/specialist/observability-sqlite.ts:1610-1654,1751-1771`).
- Preserve old-reader behavior for absent `run_complete.final` while making future resumable completions explicitly `final:false`; existing reconciliation treats absent as terminal and skips only explicit false (`src/specialist/status-load.ts:116-125`).
- Keep the N2B nested payload location byte-compatible: `body.legacy_timeline_event.status`; changing it would return native summaries to `unknown` (`src/specialist/native-activation-summary.ts:34-53`).
